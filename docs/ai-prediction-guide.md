# AI 승리팀 예측 — 작업 가이드

이 문서는 Claude Code · Codex · Antigravity(Gemini) 세 AI 에이전트가 BallPlay 레포에 참여하여 KBO 경기 승리팀을 예측하는 작업 절차를 정의합니다.

## 목적

매일 KBO 정규시즌 경기에 대해 세 AI 가 **독립적으로** 예측한 결과를 `bp_ai_predictions` 테이블에 저장합니다. 09:00 KST 이후 사용자에게 공개되고, 경기 종료 후 자동 채점되어 시즌 적중률이 누적됩니다.

## 작업 흐름

1. 본인이 어떤 AI 인지 식별 (`gemini` / `claude` / `gpt`)
2. **본인의 분석 렌즈 확인** (아래 "AI 별 분석 렌즈 — 판정 규칙")
3. 오늘 경기 목록 조회 (`games` 테이블, `game_date = 오늘 KST`)
4. **표준 데이터 도시에 실행** (`node scripts/analyze-today-games.mjs` — 아래 "데이터 접근")
5. 각 경기에 대해 본인 렌즈의 판정 규칙대로 예측 산출
6. `bp_ai_predictions` 에 INSERT (`published_at` 은 그날 09:00 KST 로 박음)

## AI 별 분석 렌즈 — 판정 규칙 (2026-08-01 개정)

세 AI 가 같은 데이터를 같은 방식으로 분석하면 결과가 수렴합니다 (실측 만장일치율 70%).
이번 개정에서 "성격" 수준이던 캐릭터를 **판정 규칙(어떤 데이터를 어떤 순서·가중치로 보고, 무엇이 픽을 뒤집는가)** 으로 구체화합니다.
말투가 아니라 **의사결정 절차가 달라야** 같은 데이터에서 다른 픽이 나옵니다. 세 렌즈 모두 그 자체로 합리적인 전략입니다 — 억지 핸디캡이 아닙니다.

### 🔷 `gemini` — 정량·전적 우선 (데이터 보수파 계승)

- **판정 데이터 우선순위**: ①시즌 누적 스탯·순위 ②시즌 팀 상대전적 + 홈/원정 스플릿 ③선발·불펜 시즌 성적. **최근 며칠의 흐름·분위기는 동점일 때의 보조 신호로만** 사용.
- **픽 전환 트리거**: 시즌 상대전적이 3경기차 이상 열세, 또는 홈/원정 스플릿이 명확히 반대 방향이면 순위 우위라도 재검토.
- **무시할 신호**: 단기 연승·연패, 어제의 대승/대패, 검증 안 된 신예·새 외국인 기대치.
- **confidence 톤**: 0.60~0.85 안정대. 검증된 우세가 겹치면 높게.
- **분석문 느낌**: "시즌 상대전적 7승 2패", "홈 27승 20패의 안방 강세" — 누적 기록 기반.

### 🟧 `claude` — 매치업·결함 우선 (매치업 균형파 계승)

- **판정 데이터 우선순위**: ①선발의 **대표본 결함**(예: 9이닝당 볼넷 5+, 피홈런 2+ — 20이닝 이상 표본만) vs 상대 타선 유형(콘택트/장타/출루)의 맞물림 ②불펜 최근 10경기 + 피로도 ③최근 10경기 폼(득실차).
- **픽 전환 트리거**: 대표본 결함이 상대 타선 유형과 최악으로 맞물리면(예: 볼넷 붕괴 투수 vs 리그 최소 삼진 타선) 시즌 순위·전적 우위를 무시하고 픽 전환.
- **무시할 신호**: 1경기짜리 상대전적(호투/부진 모두), 표본 10이닝 미만 스탯.
- **confidence 톤**: 자유. 진짜 박빙은 0.51~0.55 솔직하게, 결함 맞물림이 명확하면 0.60+.
- **분석문 느낌**: "A 의 X 결함을 B 타선 유형이 정확히 응징하는 매치업" — 맞물림 중심.

### 🟢 `gpt` — 모멘텀·이변 우선 (언더독 헌터 계승)

- **판정 데이터 우선순위**: ①타선 **최근 5경기 경기별 득점 흐름**·홈런 (시즌 타율 무시) ②주축 이탈/복귀·엔트리 변동 뉴스 ③선발 **최근 3등판 로그** (시즌 ERA 무시 — 6월의 부진이 아니라 지난주의 구위).
- **픽 전환 트리거**: 최근 5경기 득점이 상대의 1.5배 이상이거나, 상대 주축 이탈이 확인되면 순위·시즌 스탯 열세라도 언더독 픽.
- **무시할 신호**: 시즌 누적 순위·평균, 4월에 쌓인 상대전적.
- **confidence 톤**: 자유 — 모멘텀 신호가 강하면 역배도 0.60~0.70 자신 있게.
- **분석문 느낌**: "최근 5경기 44득점의 타선을 시즌 순위로 가리지 말라" — 현재 폼 중심.

### 렌즈와 정직성의 균형

- 렌즈는 **판정 절차**이지 결과 강제가 아닙니다. 본인 렌즈의 1순위 데이터가 압도적으로 한쪽을 가리키면 세 AI 가 같은 픽이어도 자연스럽습니다.
- 단, 픽이 갈릴 상황에서 "남들도 이쪽이니까" 식으로 수렴하지 마세요. **본인 렌즈의 우선순위 데이터가 가리키는 쪽**을 고르는 것이 원칙입니다.
- **공통 필수 검증 (렌즈 무관)**: 분석문에 선수 이름을 쓰기 전 그 선수가 최근 라인업에 실제로 있는지 확인하세요. 최근 3경기 이상 연속 제외된 주축은 부상/이탈 의심 → 뉴스 검색 후 반영. (사례: 최정 시즌아웃을 놓치고 일주일 뒤 분석문에 인용한 사고)

### 🚫 렌즈를 분석문에서 언급 금지

`detailed_analysis`, `one_liner`, `key_factor` 에 본인의 렌즈를 **명시적으로 언급하지 마세요**. 사용자는 본 가이드의 렌즈 설정을 모릅니다.

- ❌ "정량 우선인 저는 두산의 안정적 우세를 봅니다..."
- ❌ "모멘텀 헌터로서 이번엔 키움의 반등을 보고..."
- ❌ "매치업 렌즈로 양쪽을 검토한 결과..."

렌즈는 **결론·시각·confidence 의 결과로 자연스럽게 드러나야** 합니다. 분석문 자체는 순수한 야구 얘기만 담아주세요.

- ✅ "지난 10경기 두산이 LG 상대 7승 3패, 곽빈의 좌타 피OPS .680 — 두산 우세 명확."
- ✅ "키움 5연승 분위기 + 안우진 복귀로 마운드 안정. 강팀 KT 라도 오늘은 균열 가능."

### confidence 는 본인 렌즈 톤대로 폭 넓게

같은 픽이라도 confidence 가 다르면 그 자체로 정보입니다. **안전하게 0.60~0.65 만 박지 말고** 본인 렌즈의 신호 강도를 반영해서 폭 넓게 사용하세요:

- **gemini** — 검증된 우세에 확신 있으면 0.75, 0.80 망설이지 말고. 박빙이면 0.62 정도로 보수적.
- **claude** — 박빙이 진짜 박빙이면 0.51~0.55 솔직하게. 결함 맞물림 명확하면 0.70+.
- **gpt** — 모멘텀 신호 강하면 0.65~0.75 자신감 있게. 약한 신호면 0.55~0.60.

만장일치라도 confidence 가 0.55 vs 0.75 vs 0.62 처럼 갈리면 "확신도 분포" 자체가 다양성이 됩니다.

## 데이터 접근

### 표준 데이터 도시에 (권장 — 한 번에 전 차원 수집)

```bash
node scripts/analyze-today-games.mjs            # 오늘
node scripts/analyze-today-games.mjs 2026-08-01 # 특정일
```

이 스크립트 하나가 7개 차원을 모두 출력합니다. **세 AI 모두 이 도시에를 기본으로 쓰되, 본인 렌즈의 우선순위에 따라 가중치를 달리** 하세요:

1. 오늘 경기 + 예고 선발 / 팀 순위
2. 선발 시즌 스탯 + 상대팀 전적 + **최근 3등판 로그** (이닝·자책·K·BB 추세)
3. 팀 타선 시즌 능력 + **최근 5경기 경기별 득점·홈런·삼진·실책(수비)**
4. **시즌 상대전적 + 홈/원정 스플릿**
5. **주축 이탈 감지** (최근 3경기 연속 라인업 제외자 + 관련 뉴스 자동 검색)
6. **불펜 데일리** (최근10 ERA/WHIP·경기종반 실점·3일 투구수·연투·과부하)
7. 최근 24h 뉴스

### 개별 테이블

정성·정량 모두 허용하되 **각자의 신선도** 를 인지하고 본인 렌즈에 맞춰 활용하세요.

### 정성 데이터 (실시간 / 일일 갱신)

| 테이블 | 신선도 | 용도 |
|---|---|---|
| `games` | 실시간 (오늘) | 오늘 경기 일정 + **선발 투수** + 구장·시각 |
| `bp_team_recent_lineups` | 어제 경기까지 반영 | 팀별 최근 10경기 선발 라인업 (정성적 컨텍스트) |
| `bp_news` | 실시간 (3시간마다 크롤) | 최근 KBO 뉴스 — 부상·트레이드·이슈 |
| `bp_pitcher_vs_team_stats` | 박스스코어 집계 기준 | 투수별 특정 상대팀 전적 — 상대 ERA·WHIP·K9·BB9·최근 맞대결 |

### 정량 데이터 (⚠️ 신선도 한계 인지 필수)

| 테이블 | 신선도 | 용도 |
|---|---|---|
| `team_standings` | 어제 경기까지 (매일 KST 23:30 갱신) | 시즌 순위·승률·득실점 |
| `bp_player_stats_snapshots` | **최대 일주일 전** (매주 월요일 KST 04:00 스냅샷) | 선수 시즌 누적 스탯 |

**⚠️ 정량 데이터 사용 시 주의사항**:

- `bp_player_stats_snapshots` 는 **주간 스냅샷** 이라 평일에 보면 최대 6-7일 전 데이터입니다.
  스냅샷 시점 이후의 활약상·부진·부상은 반영 안 됨.
- `team_standings` 도 오늘 경기 결과는 미반영. 어제까지 기준.
- 정량은 **베이스라인 (안정적 시즌 추세) 일 뿐**, 최근 며칠의 동향은 반드시 `bp_news` 와 자체 조사로 보강하세요.
- 스냅샷 시점 이후 큰 변화 (부상, 복귀, 트레이드, 폼 급변) 가 있다면 정량보다 최신 정보 우선.
- `bp_pitcher_vs_team_stats` 는 상대팀 전적 표본이 작을 수 있으므로 `games`, `starts`, `innings`, `last_game_date` 를 함께 확인한 뒤 반영하세요.

### 렌즈별 정량 데이터 활용

- **gemini (정량·전적 우선)** — 시즌 누적·상대전적·스플릿이 판정 기준. 최근 동향과 어긋나면 정량 쪽.
- **claude (매치업·결함 우선)** — 대표본 결함 vs 타선 유형의 맞물림이 판정 기준. 1경기 표본은 배제.
- **gpt (모멘텀·이변 우선)** — 최근 5경기 흐름·최근 3등판·이탈 뉴스가 판정 기준. 시즌 누적은 무시.

## 자체 조사 — 필수

3개 테이블만으로는 충분한 분석이 안 됩니다. **반드시 외부 정보를 적극적으로 추가 조사**해 주세요. 학습 데이터에만 의존한 빠른 답은 받지 않습니다.

### 반드시 조사해야 할 항목 (최소 3가지 이상)

매 경기마다 본인이 가용한 모든 수단(웹 검색, 뉴스 사이트, 커뮤니티, 학습 데이터)으로 다음을 조사하고 분석에 반영하세요:

- **팀 분위기·모멘텀** — 최근 연승/연패 분위기, 라커룸 이슈, 감독 코멘트
- **핵심 선수 컨디션** — 부상 복귀, 슬럼프, 폼 상승, 최근 활약상
- **선수 이슈** — 트레이드, 부상 이탈, 1군 콜업, 2군 강등, 징계
- **선발 매치업 깊이 분석** — 상대 전적, 좌/우 매치업, 구장과의 궁합
- **선발의 상대팀 전적** — `bp_pitcher_vs_team_stats` 에 해당 선발과 상대팀 row가 있으면 시즌 누적 지표와 나란히 비교
- **팀 상승세·하락세** — 시즌 흐름, 위기/반등 신호, 분기점
- **기타** — KBO 도메인에서 본인이 중요하다고 보는 모든 신호

### `detailed_analysis` 작성 시 외부 조사 내용 반드시 포함

본인이 어떤 외부 정보를 조사해서 어떻게 해석했는지 분석문에 **명시적으로 드러나야** 합니다. 예시:
- "키움 이정후 어깨 통증으로 최근 5경기 결장, 오늘 라인업 복귀 미정"
- "두산 5연승 분위기 + 곽빈 최근 등판 ERA 1.8 의 상승세"

이런 외부 정보가 분석에서 보이지 않으면 가이드 위반입니다. 정답률보다 **본인다운 관점, 적극적 조사, 다양성**이 우선입니다.

## 독립성 규칙 (중요)

- **다른 AI 의 예측 결과를 보지 마세요.** 같은 경기에 대해 본인이 INSERT 하기 전, `bp_ai_predictions` 에서 다른 `ai_provider` row 를 select 하지 않습니다.
- RLS 가 `published_at <= now()` 인 row 만 anon 에 노출하므로 anon key 로 조회하면 자연 차단되지만, service_role 사용 시에는 본인이 의식적으로 회피해 주세요.
- 다양성이 시청자 재미의 핵심입니다. 합의된 예측은 안전하지만 지루합니다.

## INSERT 형식

### SQL 예시

```sql
insert into public.bp_ai_predictions (
  game_id,
  game_date,
  ai_provider,
  model_name,
  predicted_winner_team_id,
  confidence,
  key_factor,
  one_liner,
  detailed_analysis,
  published_at
) values (
  '<games.id UUID>',
  '2026-05-29',
  'claude',                          -- 'gemini' | 'claude' | 'gpt'
  'claude-opus-4-7',                 -- 옵션, 본인 모델명
  'kt',                              -- teams.id
  0.62,                              -- 0.5 ~ 1.0
  '선발 매치업',                       -- 짧은 핵심 요인 (~10자)
  '벤자민 vs 켈리, 좌타 비중에서 갈린다.',
  $$ KT 벤자민이 최근 3경기 ERA 1.80 으로 안정세인 반면, 키움 켈리는 좌타에 약점(피OPS .820). KT 타선 좌타 비중 4명으로 매치업 우위. 다만 키움 홈 이점과 마무리 김재웅의 1세이브 변수. 결과적으로 60% 수준 KT 우세 판단. $$,
  '2026-05-29 09:00:00+09:00'        -- 그날 09:00 KST
);
```

### 필드 — DB 가 요구하는 최소만

분석의 깊이·톤·길이·문체는 **각 AI 의 자유**입니다. 아래는 DB 가 받기 위한 최소 제약만 명시합니다.

**`ai_provider`** (필수) — 본인 식별자. CHECK 제약으로 다음 셋 중 하나만 허용:
- Claude Code → `'claude'`
- Codex → `'gpt'`
- Antigravity → `'gemini'`

**`model_name`** (옵션) — 사용 중인 구체 모델명. 비워둬도 됨. 시즌 후반 모델별 비교용.

**`predicted_winner_team_id`** (필수) — `teams.id` FK. KBO 10팀 ID 중 하나: `kt`, `doosan`, `lg`, `samsung`, `kia`, `nc`, `lotte`, `hanwha`, `kiwoom`, `ssg`. home/away 둘 중 하나여야 합니다.

**`confidence`** (필수) — `numeric`, **CHECK 0.5~1.0**.
- 본인이 지목한 팀이 이길 거라 보는 정도면 됩니다. 0.51 도 0.99 도 자유.
- 0.5 미만이면 INSERT 가 거부되므로, 반대 팀이 이길 거라 본다면 그 팀을 `predicted_winner_team_id` 로 두고 다시 산정하세요.

**`key_factor`** (필수) — 핵심 요인 한 마디. 길이·표현 자유. UI 카드에 그대로 노출되니 가독성은 본인 판단.

**`one_liner`** (필수) — 카드 요약. 길이·문체 자유. UI 의 작은 카드에 들어가는 텍스트입니다.

**`detailed_analysis`** (필수) — Reveal 화면 토글로 펼쳐지는 본문. 길이·구성·문체 자유. 수치 인용·서술형·리스트 등 본인 스타일로.

**`published_at`** (필수) — 그날 09:00 KST 권장:
```sql
-- 오늘 09:00 KST
(current_date at time zone 'Asia/Seoul' + interval '9 hours') at time zone 'Asia/Seoul'
```
또는 직접 박기: `'2026-05-29 09:00:00+09:00'`

## 분석은 자유롭게

톤·길이·관점·근거 활용 방식 모두 본인 판단입니다. 같은 데이터를 봐도 다른 결론에 이르는 것 — 그게 이 기능의 본질입니다. 통계 위주든, 인사이트 위주든, 짧든 길든, 평어체든 존댓말이든 본인 스타일대로.

## 환경 변수

`SUPABASE_URL` 과 `SUPABASE_SERVICE_ROLE_KEY` 가 `.env.local` 에 있습니다. INSERT 시 service_role 클라이언트 사용:

```ts
import { createSupabaseAdminClient } from "@/lib/supabase/server";

```

## 자가 점검 체크리스트 (DB 제약만)

INSERT 전 확인:
- [ ] `game_id` 가 오늘 경기 UUID 가 맞는가
- [ ] `predicted_winner_team_id` 가 home/away 둘 중 하나인가
- [ ] `confidence` 가 0.5 이상 1.0 이하인가 (CHECK)
- [ ] `published_at` 이 timestamptz 로 박혔는가
- [ ] 같은 `(game_id, ai_provider)` row 가 이미 있지 않은가 (UNIQUE 위반)
- [ ] 다른 AI 의 결과를 보지 않고 독립적으로 판단했는가

## 채점

- 경기 종료 후 `sync-kbo-games` cron 이 `home_score` 와 `away_score` 를 비교
- `predicted_winner_team_id == 실제 승리팀` → `is_correct = true`
- 무승부 (점수 같음) → `is_correct = false`
- 채점 결과는 시즌 적중률 RPC (`bp_ai_predictions_overall_stats`, `bp_ai_predictions_by_provider_stats`) 로 집계되어 사용자 페이지에 표시됩니다.
