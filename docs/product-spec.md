## 1. 한 줄 요약

> **야구놀이터** — KBO 팬을 위한 가벼운 웹 놀이터.
> v1의 첫 미니게임은 **라인업 대결**: "내가 짠 KBO 라인업으로, 다른 사람이 짠 라인업과 AI 가상 대결을 붙여 9회 텍스트 중계와 승패 결과를 받아본다."

라인업 빌더(짜는 재미) → 대결(붙이는 재미) → 랭킹·공유(자랑하는 재미) 의 3단 루프가 v1 핵심.

야구놀이터는 **우산 브랜드**로, 향후 승부 예측·트레이드 시뮬·명장면 퀴즈 등 야구 미니게임을 같은 우산 아래 확장할 수 있도록 구조를 설계한다 (§11 v4+ 참조).

## 2. 왜 만드는가 (Vision)

- **단순 라인업 빌더는 1회성 콘텐츠다.** 한 번 짜면 끝.
- 여기에 **"붙여본다"** 가 붙는 순간, 재방문 동기·공유 동기·로그인 동기가 동시에 생긴다.
- **AI 9회 텍스트 중계 + 라이트 화면 연출**은 단순 스코어 예측과 결정적으로 다른 경험을 만든다. 매 경기가 다른 서사 → 매번 다른 콘텐츠 → 공유될 만한 결과물.
- KBO 데이터(Statiz 등)를 **정성껏 정제해서** AI에게 먹이면, "그럴듯한 픽션"이 아니라 **"오 이거 진짜네"** 가 나오고, 이 순간이 제품의 차별점이 된다.

## 3. 시장 환경 (Market Landscape)

2026-05-21 기준 시장 조사 결과 — **동일한 컨셉의 서비스는 발견되지 않음**. 구성 요소별 인접 서비스만 존재.

### 3.1 인접 경쟁자

| 서비스 | 지역 | 같은 점 | 다른 점 (= 우리 차별점) |
|---|---|---|---|
| **WhatIfSports SimMatchup / Dream Teams** | US | 유저 vs 유저 라인업 대결 + 승패 누적 (컨셉 가장 유사) | MLB 역대 선수, 통계 엔진(LLM X), 박스스코어 위주, UI 2000년대급, 영어 |
| **FanGraphs Baseball Sim** | US | 라인업 직접 짜서 매치업, 10,000회 시뮬 분포 | MLB·통계 기반, 텍스트 중계 없음, PvP/소셜 없음, 영어 |
| **Diamond Mind Online (Imagine Sports)** | US | 유저 매치 + play-by-play 중계 | 유료 구독, MLB 역대, 결정형 엔진(LLM 자유서술 아님) |
| **KBO LABS / hogoos** | KR | KBO + AI 예측 | **실경기 베팅 예측용**, 라인업 PvP·텍스트 중계 없음 |
| **9UP·컴투스프로야구·마구마구** | KR | KBO + 시뮬 | **모바일 매니저 게임**, 가벼운 웹 매치업·LLM 중계와 카테고리 자체가 다름 |
| **KBO-GPT 류 커스텀 GPT** | KR | KBO + LLM | Q&A 챗봇일 뿐, 매치업·라인업 빌더 없음 |

### 3.2 시장 빈 자리

다음 4가지 조합은 검색으로 발견되지 않음:
- **KBO 특화 시뮬레이션 엔진** (실데이터·세이버 지표 반영, 한국어)
- **사용자 간 PvP 라인업 매치 + 시드 기반 재현 가능 결과**
- **모바일/SNS 친화 결과 카드** (캡쳐·공유 친화)
- **가벼운 웹 + 무로그인 진입** (게임이 아닌 콘텐츠로 포지셔닝)

한국 시장 인식이 "KBO 시뮬 = 유료 모바일 매니저 게임"으로 굳어 있어, **가벼운 웹 + 무로그인 + 카톡 공유 카드** 라는 포지션이 명확한 차별점이 된다. 게임이 아니라 "콘텐츠/놀이"라는 점도 차별점.

**참고**: v1엔 LLM을 사용하지 않으나(§7), KBO에 한국어 LLM 분석을 결합한 콘텐츠는 v1.1+ 확장 시 빠르게 진입 가능한 추가 차별점.

### 3.3 참고할 만한 인사이트

- **FanGraphs Sim**: 시뮬 결과를 분포 그래프로 시각화 → "AI가 던진 결과의 통계적 근거"를 표현하는 방식 차용 가치 (§7.3 관련)
- **WhatIfSports Dream Teams**: 유저 팀 누적 승패가 retention 핵심 루프 → §6.4 랭킹 설계와 정확히 일치하므로 그대로 매핑 가능
- **KBO-GPT 인기**: 한국 야구팬의 LLM 분석 수요는 이미 검증됨 → "분석 챗봇"에 익숙한 사용자를 "대결 + 공유" 깔때기로 전환 가능

### 3.4 조사 한계

X·디시·에펨코리아 등 한국 커뮤니티의 비공개 사이드 프로젝트는 공개 웹 검색에 잘 잡히지 않음. "없다"가 아니라 **"공개 웹 검색으로는 못 찾았다"**가 정확. 출시 직전 한국어 키워드("KBO AI 시뮬", "라인업 대결" 등)로 정성 모니터링 권장.

## 4. 핵심 사용자 시나리오

### 시나리오 A — 부모와 자녀
1. 아빠가 한화 라인업을 짠다.
2. 아들이 LG 라인업을 짠다.
3. 둘 다 저장 → 라인업 리스트에 올라간다.
4. 아빠가 아들 라인업을 골라 "대결" → 9회 텍스트 중계가 흐름.
5. 결과 카드를 캡쳐해서 가족 단톡방에 공유. 다음날 또 한다.

### 시나리오 B — 친구와의 도전장
1. 라인업을 짠 뒤 "대결 신청" 버튼 → SNS 공유 링크 생성.
2. 친구가 링크 받고 들어와서 자기 라인업을 짠다(또는 기존 거 사용).
3. 자동으로 매치업 성사 → 결과 페이지에서 둘 다 결과 확인.
4. 승자에게 포인트/랭킹 점수가 누적.

### 시나리오 C — 매칭풀에서 도전
1. "라인업 리스트" 탭에서 다른 사람들의 공개 라인업이 뜬다.
2. 도전할 라인업을 골라 내 라인업과 매치 → 결과 확인.
3. 승률·랭킹이 누적된다.

## 5. 앱 구조 / 네비게이션

### 5.1 하단 4탭 구조

| 탭 | 역할 | v1 범위 |
|---|---|---|
| **홈** | 랭킹·공지·KBO 소식 등 진입 허브 | 오늘의 매치업 + 주간 랭킹 위주 (정보 과부하 방지) |
| **라인업짜기** | 라인업 생성·편집 + **내 라인업 목록 (source of truth)** | 빌더 + 저장 목록 |
| **경기장** | 다른 사람 라인업과의 매치업 흐름 | 4단계 플로우 (§5.3) |
| **마이** | 내 전적·프로필·닉네임·사진·설정 | 전적·기본 프로필 |

### 5.2 라인업 목록의 동기화

- **Source of truth**: 라인업짜기 탭의 "내 라인업 목록"
- **경기장 탭에서도 접근**: 경기 전 "출전 라인업 선택" 시 같은 목록을 호출
- 두 곳은 같은 데이터를 다른 컨텍스트(편집용 vs 출전 선택용)로 보여줄 뿐, 사실상 동일 리스트

### 5.3 경기장 4단계 흐름

```
[로비] → [경기장 입장] → [시뮬레이션] → [결과]
```

1. **로비** — 매칭풀(다른 사람들의 공개 라인업) 둘러보기. 팀별·최신순·인기순 필터
2. **경기장 입장** — 상대 라인업 확정 + **내 출전 라인업 선택** + 매치 미리보기 (양 팀 요약, 선발 투수 비교 등)
3. **시뮬레이션** — 9회 텍스트 중계 진행 (타이핑 효과 + 결정적 순간 연출)
4. **결과** — 최종 스코어 · MVP · 총평 · 공유 카드 · "다시 대결" 버튼

이 4단계는 모바일 게임의 클래식 패턴(로비/입장/진행/결과)이라 학습 비용이 거의 없음. "경기장 입장" 단계에서 출전 라인업을 직접 선택하게 함으로써 "내가 시켰다"는 주체감과 결과에 대한 기대감(anticipation)이 만들어진다.

### 5.4 v1에서의 홈 탭 가이드

홈은 너무 비어있으면 안 되고, 그렇다고 v1부터 다 채우면 데이터 파이프라인 부담이 큼. 균형을 잡기 위해:

- **상단**: 오늘의 매치업 / 화제의 매치 하이라이트 1~2개
- **중단**: 주간 또는 일간 랭킹 Top 5~10
- **하단**: 공지 + KBO 간단 소식 (헤드라인 정도, v2에서 본격 확장)

뉴스 본격 노출은 출처·저작권 정리가 필요하므로 v2 이후.

### 5.5 디자인 톤

**v1 = 라이트 단일 톤**으로 결정 (2026-05-22).

기존 톡구장 다크 톤은 "프로 야구팬·하드코어" 결이었지만, 야구놀이터는 **"놀이터" 우산 + 가족 친화 + SNS 바이럴** 포지셔닝이라 라이트 톤이 더 정합. 특히:

- 부모-자녀 시나리오(§4-A)·무로그인 진입 친화 → 친근한 라이트
- **결과 카드의 SNS 공유 일관성** — 모든 사용자가 같은 톤 카드를 공유해야 브랜드 노출 누적
- 가벼운 정보 콘텐츠(홈 탭의 랭킹·소식 등) 가독성 우선

**구조 원칙: 시맨틱 토큰 기반 설계**
- Tailwind + shadcn/ui 패턴의 시맨틱 토큰 사용 (`--background`, `--foreground`, `--primary` 등)
- v1엔 라이트 팔레트만 정의, 다크 추가 시 미래 비용 ↓ (토큰 값만 추가)
- 결과 카드는 사용자 설정과 무관하게 **항상 라이트** (공유 일관성)

**컬러 전략: 중성 베이스 + KBO 팀 컬러 주도**

토스/MLB/네이버 스포츠 같은 "신뢰·전문성" 시그널의 파란색을 메인으로 두는 대신, **베이스는 중성(라이트 그레이/베이지) + 컬러는 KBO 10팀이 주도**한다. 이유:
- 사용자가 보는 거의 모든 화면에 KBO 라인업이 들어가므로 팀 컬러가 자동으로 메인이 되는 게 자연스러움
- 메인 컬러 하나를 정하는 부담 없이 콘텐츠별 다양성 자동 확보 (Spotify Wrapped 패턴)
- 결과 카드가 SNS에 흩뿌려질 때 매번 다른 팀 컬러 = 시각적 다양성·바이럴
- 사용자에게 "내 응원팀 컬러가 내 앱에 있다"는 친밀감

**팔레트 (2026-05-22 토큰화 완료)**
- 베이스: `--bp-bg` `#fafafa` / `--bp-card` `#ffffff` / `--bp-bg-soft` `#f5f6f8`
- 텍스트: `--bp-text` `#1a1a1a` / `--bp-text-secondary` `#4b5563` / `--bp-text-muted` `#6b7280`
- 라인: `--bp-line` `#eceef2`
- 상태: `--bp-success` `#16a34a` / `--bp-danger` `#dc2626` / `--bp-info` `#2563eb`
- 게임감 액센트: `--bp-accent` `#ff6b35` (CTA) / `--bp-game-victory` `#00e676` (승리)
- KBO 10팀: `--team-{doosan|lg|kt|ssg|nc|kiwoom|samsung|lotte|kia|hanwha}` + 각 `-soft` (옅은 배경용). `lib/constants/teams.ts`의 `team.color`와 동기화.

전체 토큰은 `app/globals.css` + `tailwind.config.ts` 참조. 사용 예: `bg-bp-card`, `text-team-doosan`, `bg-team-hanwha-soft`.

**참고 레퍼런스**
- Spotify / Apple Music: 콘텐츠 dominant color → UI 톤 (chromatic content 패턴)
- ESPN / MLB 팀 페이지: 팀 컬러가 화면 톤 주도
- 무신사 / 29CM: 중성 베이스 + 콘텐츠 컬러

**선택적 확장 (v2+)**
- 시뮬레이션 진행 화면은 "야구장 야간경기" 분위기로 부분 다크 액센트 검토 가능
- 사용자 라이트/다크 토글은 v2 이후, 피드백 누적 시 추가

## 6. 핵심 기능

### 6.1 라인업 빌더 (기존, 유지)
- 정적 JSON 시드 기반 KBO 실데이터
- 탭-탭 → 드래그 입력
- 저장 시 라인업 메타(이름, 팀, 작성자) 함께 저장

### 6.2 라인업 리스트 (신규)
- 내 라인업 + 다른 사람들의 공개 라인업
- 필터: 팀별, 최신순, 인기순(대결 횟수/승률)
- 카드형 UI, 각 라인업에 "대결" 버튼

### 6.3 가상 대결 (시뮬 엔진 기반)
- **입력**: 양 팀 라인업 + KBO 데이터 스냅샷 + 시드(seed)
- **처리**: **시뮬레이션 엔진** (§7 참조). 9이닝 진행을 코드 로직이 결정. v1엔 LLM 사용하지 않고, v1.1+에서 자연어 윤문(매치 미리보기·총평·결정적 순간 멘트)을 선택적으로 추가.
- **출력 형식**:
  - 이닝별 짧은 텍스트 (1회초 ~ 9회말, 연장 가능)  
    예시: `1회초 김도영: 안타 / 강백호: 삼진 / 노시환: 플라이아웃`
  - 주요 이벤트(홈런·도루·역전타) 강조
  - 최종 스코어 + MVP + 짧은 총평
- **연출**: 텍스트가 타이핑 효과로 흐르고, 결정적 순간에 짧은 애니메이션/사운드 (라이트 연출, 과한 그래픽 없음)
- **재현성**: 시드 기반이라 같은 매치업+같은 시드로 정확히 같은 결과 재생 가능. "다시 대결"은 의도적으로 다른 시드.

### 6.4 결과 저장 & 랭킹
- 개인 전적 (승/패/무, 최근 폼)
- 팀별 랭킹 (어느 팀 라인업이 가장 강한가)
- 라인업별 누적 승률
- 시즌 개념 (월간 또는 분기 리셋 검토)

### 6.5 공유 / 도전장
- 결과 카드 이미지 생성 (캡쳐용)
- "대결 신청" 링크 — SNS 공유 시 상대가 들어오면 자동 매치업 페이지로 진입
- 카카오톡/X/인스타 공유 버튼

## 7. 시뮬레이션 엔진 설계

**핵심 원칙: 경기 진행은 100% 코드 로직, LLM은 v1에서 사용하지 않음. v1.1+에서 자연어 표현(매치 미리보기·총평·결정적 순간 멘트)을 위한 선택적 토핑으로만 도입.**

야구 시뮬레이션의 "분석"은 본질적으로 통계·확률 모델의 영역이지 LLM의 강점이 아니다. 시장에서 검증된 시뮬레이터(Out of the Park Baseball, Diamond Mind, FanGraphs Sim)는 모두 룰베이스 엔진. LLM은 자연어 출력이 의미 있는 자리에만 선택적으로 활용한다. (2026-05-22 결정)

### 7.1 아키텍처

```
[데이터 레이어]  ── Statiz / KBO 공식 / 네이버 (사전 캐싱)
       ↓
[시뮬레이션 엔진 (TypeScript)]
       - 확률 모델 + 시드 기반 무작위 추첨
       - 9이닝 진행 (베이스 상태·아웃카운트)
       - 결정론적 + 재현 가능
       ↓
[자연어 출력 (v1엔 단순 텍스트, v1.1+ LLM 윤문 옵션)]
       - 결과 자체는 항상 코드가 결정
       - LLM은 "같은 결과를 다양한 표현으로" 윤문 역할만
```

### 7.2 데이터 레이어 (엔진에 무엇을 넣을까)

**정적 데이터** (시즌 시작 시 1회 시드)
- 타자: 타율(AVG)·출루율(OBP)·장타율(SLG)·홈런·도루·안타
- 투수: ERA·WHIP·K/9·BB/9·승/패/세이브
- 세이버 지표: wRC+, WAR, FIP (Statiz 강점)

**동적 데이터** (v1.1+ 보강)
- 최근 7~10경기 폼
- 부상/엔트리 상태
- 좌우 상성, 구장별 split

**정성 데이터** (v2+ 보강, LLM 사전 정제)
- 팀 분위기 한 줄 (연승/연패/내홍 등)
- 주요 부상/트레이드 헤드라인

**v1 최소 셋업** (가장 빠른 길)
- Statiz에서 10개 구단 × ~40인 = ~400명을 **1회 수동 시드** → `data/kbo_players_2026.json`
- 일정/결과만 일 1회 cron으로 갱신 (Vercel cron / Supabase edge function)
- 최근 폼·뉴스는 v1.1+로 미룸
- 엔진 입력 = 선수당 ~15필드 (이름·팀·포지션·AVG/OBP/SLG/HR/SB/wRC+ + 투수는 ERA/WHIP/K9/BB9/FIP)

### 7.3 시뮬레이션 엔진 (코어)

```typescript
// 의사 코드
function simulateGame(
  homeLineup: Lineup,
  awayLineup: Lineup,
  context: GameContext,  // 구장·날씨·홈/원정
  seed: number           // 무작위 추첨용 시드
): GameResult {
  const rng = seedRandom(seed);
  const state = initialState();

  for (let inning = 1; inning <= 9; inning++) {
    for (const half of ['top', 'bottom']) {
      const battingTeam  = half === 'top' ? awayLineup : homeLineup;
      const pitchingTeam = half === 'top' ? homeLineup : awayLineup;
      while (state.outs < 3) {
        const batter  = battingTeam.nextBatter();
        const pitcher = pitchingTeam.currentPitcher();
        const outcome = drawAtBatOutcome(batter, pitcher, context, rng);
        // outcome: K | GO | FO | 1B | 2B | 3B | HR | BB | HBP | SF …
        applyOutcome(state, outcome);
      }
    }
  }
  return { score, events, mvp, seed };  // seed 포함 → 재현 가능
}
```

**확률 모델**
- 타자 stats × 투수 stats × 좌우 상성 × 구장 보정 → 결과 확률 분포
- KBO 평균을 anchor로 두고 양 선수의 상대적 편차로 조정
- 단순 anchor 예시: `[삼진 22%, 땅볼아웃 24%, 플라이아웃 18%, 1루타 18%, 2루타 5%, 3루타 0.5%, 홈런 4%, 볼넷 8%, 사구 0.5%]`

**무작위성 통제**
- 시드 기반 RNG (`seedrandom` 등)
- 같은 시드 + 같은 라인업 = **같은 결과** (재현 가능)
- "다시 대결" 버튼은 다른 시드 → 다른 결과 (의도된 변동)
- 시드를 매치 결과에 함께 저장 → 사용자가 결과를 재생 가능

**변동성 폭 (재미 vs 신뢰성)**
- 너무 좁으면 강팀이 항상 이김 (재미↓)
- 너무 넓으면 약팀이 자주 이김 (신뢰성↓)
- 목표: 60대40 우열에서 ±2~3점 변동 폭. 베타 트래픽 보고 튜닝.

### 7.4 자연어 출력 레이어

**v1 (LLM 없음)** — 시뮬 엔진 결과를 짧은 텍스트로 그대로 출력
```
1회초 김도영: 안타
1회초 강백호: 삼진
1회초 노시환: 플라이아웃
1회말 ...
```
LLM 없이도 게임 성립. 비용 0원. 출시 빠름.

**v1.1+ (선택적 LLM 윤문)** — 자연어가 진짜 가치 있는 자리에만
- **매치 미리보기** (입장 단계): "한화 라인업은 좌투에 강함. LG 선발은 좌투 손형주" 같은 한 단락
- **결정적 순간 멘트** (시뮬 진행 중): 만루·역전 등 1~2회만 짧은 멘트
- **결과 총평** (결과 화면): MVP 1~2줄 코멘트 + 경기 흐름 요약

모델 전략은 §12 참조. Provider 추상화로 Gemini Flash 무료 → Claude Haiku 4.5 / GPT-4o-mini 전환 가능. 매치당 비용 ~0.7~5원 수준이라 §10 포인트 경제와 정합.

### 7.5 페르소나 톤 (v1.1+ LLM 도입 시)

- 캐스터(중립적 진행) + 해설위원(분석·드립) 2인 구도
- KBO 특유의 중계 어투 (e.g. "쳤습니다, 쭉쭉 뻗어갑니다!")
- 시스템 프롬프트로 톤 고정 + 프롬프트 캐싱으로 비용 절감

### 7.6 결과 캐싱

- 키: `(라인업A_id, 라인업B_id, 데이터스냅샷날짜, 시드)`
- 동일 매치업+동일 시드 재시뮬 시 DB 조회만 (엔진·LLM 호출 X)
- "다시 대결" 버튼은 의도적으로 다른 시드 → 새 캐시 엔트리 생성
- LLM 호출은 결과별 1회만 — 같은 결과를 다시 보면 캐시된 텍스트 재사용

## 9. 법적·저작권 가이드

KBO 팀명·선수 실명·통계를 사용하는 시뮬레이션 서비스로서 한국 법상 **회색지대**에 위치한다. 본 가이드는 법무 자문이 아닌 운영 원칙이며, **v2 유료화 직전 변호사 자문 필수**. (2026-05-22 정리)

### 9.1 위험 카테고리

| 영역 | 위험 수준 | 비고 |
|---|---|---|
| **팀 공식 로고·심볼** | 높음 (상표/저작권 명확) | **사용 금지** |
| **선수 사진·이미지** | 높음 (퍼블리시티권) | **사용 금지** |
| 팀명 (한화 이글스 등) | 회색지대 | 정보 제공·평론에선 관용, 게임화하면 위험↑ |
| 선수 실명 | 회색지대 | 통계 컨텍스트 안에선 허용 (Statiz·네이버스포츠 관행) |
| 통계 수치 | 낮음 (사실은 저작권 X) | 출처 사이트 이용약관은 별개 이슈 |
| **유료화** | 위험 증폭 | 상업적 이용 = 라이선스 요구 명분 명확화 |

### 9.2 운영 원칙

**절대 사용 안 함**
- 팀 공식 로고·심볼·마크
- 선수 사진·이미지·모션
- KBO·KBOP 공식 자산 일체

**사용 가능 — 다만 매너·표기 의무**
- 팀명 (텍스트로만)
- 선수 실명 (통계·라인업 컨텍스트)
- 팀 컬러 (자체 분석 기반, `lib/constants/teams.ts`)
- 시즌 스탯 (출처 표기 필수)

**시각 표현 대체 — 이미 결정된 방향**
- 팀 로고 자리 → **이니셜 + 팀 컬러 원형 뱃지** (`TeamBadge` 컴포넌트)
- 선수 사진 자리 → **이름·등번호·포지션 뱃지**
- 결과 카드 → 텍스트·도형 중심, 공식 자산 0

### 9.3 디스클레이머 / 표기 의무

**푸터 · About 페이지 필수 문구**
> 본 서비스(야구놀이터)는 KBO·KBOP·각 구단과 무관한 비공식 팬 메이드 서비스입니다. 모든 팀명·선수명은 정보 제공 목적이며, 저작권은 각 권리자에게 있습니다.

**데이터 출처 표기**
- 라인업·통계 화면에 작은 라벨: "데이터: Statiz"
- KBO 공식 일정 사용 시: "일정: KBO 공식"

### 9.4 단계별 위험·대응

| 단계 | 실질 위험 | 대응 |
|---|---|---|
| v1 무료 베타 (트래픽 작음) | 매우 낮음 | 본 가이드 원칙 준수만 |
| v1 무료 (>1만 DAU 추정) | 낮음~중간 | KBOP·구단 인지 시 cease and desist 가능 — 대응 매뉴얼 준비 |
| **v2 유료화 직전** | 중간~높음 | **변호사 자문 필수**. 라이선스 vs 재구조화 옵션 평가 |
| v3 본격 성장 | 높음 | 라이선스 협상 또는 추상화 피벗 |

### 9.5 백업 시나리오 (위험 현실화 시)

cease and desist 등 법적 압박이 들어오면 즉시 대응:

1. 즉시 **무료화 + 디스클레이머 강화**
2. 1차 협상 시도 (소규모 라이선스 옵션 탐색)
3. 협상 실패 시 — **추상화 피벗**:
   - 팀명: "한화 이글스" → "오렌지 이글스" 같은 변형, 또는 사용자 커스텀
   - 선수명: 가상 캐릭터 또는 사용자 입력
   - 게임 본체·시뮬 엔진은 유지, **표면 식별자만 추상화**

**이 백업이 가능하도록 코드 구조 결정** (사전 방어 설계)
- 팀·선수 데이터를 한 곳에 격리 (`lib/constants/teams.ts`, `data/kbo_players_*.json`)
- 컴포넌트는 `teamId`·`playerId`만 받고 표시는 데이터 파일에서 조회
- 추상화 피벗 시 **데이터 파일만 갈아끼우면** 시뮬 엔진·UI 무손상

### 9.6 변호사 자문 시점

다음 시점에 반드시 자문:
- 유료 결제 도입 직전 (§10 BM 적용 전)
- 트래픽 1만 DAU 도달 시
- KBOP·구단으로부터 공식 문의·항의 수신 시
- 외부 투자·기업 협력 논의 시작 시

## 10. 비즈니스 모델 / 로그인 명분

**"대결 = 로그인 필수"** 로 잠근 구조. 라인업 빌더는 누구나 자유롭게 쓸 수 있고, "다른 사람과 붙여본다"는 순간부터 가치 단계가 올라가는 깔때기.

### 10.1 핵심 원칙
- **페이월이 아니라 "더 즐기려면"** 구조 — 무료로도 충분히 재밌어야 함
- **단일 통화: 포인트** — 무료 일일 지급 / 즉시 충전 / 패스 자동 지급 모두 같은 화폐로 통일
- AI 호출 비용이 실제로 들어가는 구조라 "대결권 = 포인트" 명분이 자연스러움

### 10.2 단계별 권한 (가안)

| 구분 | 라인업 슬롯 | 대결 가능 | 포인트 | 비고 |
|---|---|---|---|---|
| **비로그인** | 1개 | ❌ 불가 | — | 라인업 짜기 + 카드 공유까지만. 도전장 링크 수신 시 가입 유도 페이지로 |
| **무료 로그인** | 3개 | ✅ 가능 | 일일 무료 포인트 지급 (수치 §10.4 TBD) | 랭킹 등록 가능 |
| **패스 구독자** | 5~10개 | ✅ 가능 | 매일 자동 포인트 지급 (수치 §10.4 TBD) | 슬롯 확장 + 매일 보상 |

비로그인은 라인업을 짜고 카드로 공유까지는 가능 — 진입 장벽을 낮춰 잠재 사용자를 끌어들이는 역할. 다만 "대결"이라는 핵심 경험은 로그인 사용자 전용.

### 10.3 대결 비용 정책

- **도전하는 사람만 포인트 소모** (challenger pays)
- **도전받는 사람은 포인트 소모 없음** → 친구 도전장은 받는 입장에서 부담 없이 응할 수 있어 바이럴 친화적
- 비로그인이 도전장 링크를 받으면 → 가입 유도 페이지로 진입 (도전에 응하려면 가입)
- 매칭풀(로비)에서 다른 사람의 공개 라인업에 도전하는 경우도 동일하게 도전자가 부담

### 10.4 포인트 경제 (수치 TBD — 배포 시점 결정)

배포 직전 다음 항목을 확정:
- 대결 1회당 소모 포인트
- 무료 로그인의 일일 무료 지급량 (= 일 N회 무료 대결)
- 패스 구독자의 일일 자동 지급량
- 충전 단위 / 가격 (소액결제)
- 신규 가입 보너스 / 매일 출석 보너스

수치는 베타 트래픽·AI 비용 추정·체감 테스트를 통해 결정. 사전에 너무 후하게 풀면 BM 약해지고, 너무 박하게 잡으면 첫 인상이 "쪼잔하다" 가 됨.

### 10.5 게임 패스 형태 (가안 — 배포 시점 결정)

세 가지 옵션 후보:

- **월 정액 구독** — 자동 갱신, retention 강함. 일부 사용자는 구독 자체에 거부감
- **기간제 일회성 구매** — 30일권 등, 만료 시 갱신 X. 결제 부담↓, 재구매 동기는 사용자에게 의존
- **하이브리드** — 둘 다 제공해 사용자 선호에 맡김

배포 직전 가격대 · 형태 · 추가 혜택(전용 뱃지, 시즌 한정 슬롯, 결과 카드 프리미엄 스킨 등)을 함께 결정.

**신규 도입 (v1.1+ 보류)**
- **LLM Provider 추상화**: Vercel AI SDK 또는 직접 추상화. 환경변수로 provider 한 줄 전환 가능하게.
- **LLM 모델 전략** (매치당 비용 기준):
  - **v1.1 베타**: Gemini 2.5 Flash 무료 — 일 1,500매치 한도. 학습 데이터 약관 명시 필요.
  - **트래픽 증가 시**: GPT-4o-mini (~0.7원/매치) 또는 Claude Haiku 4.5 (~5원/매치) 로 전환.
  - **선택 기준**: 한국어 짧은 멘트 품질 차이는 미미. 비용 우선이면 GPT-4o-mini, Claude Code 워크플로 정합성 + 캐싱 효과 우선이면 Claude Haiku.
- **이미지 생성** (결과 카드): Satori / `@vercel/og` (SNS 공유용 PNG)

**의존성 추가 시 원칙**
- v1엔 의존성 최소. 새 라이브러리는 명확한 이유 있을 때만.
