# AI 종합분석 리포트 — 작성 가이드

3개 AI(gpt/gemini/claude)의 승리팀 예측이 모두 입력된 뒤, 경기별 **종합분석 리포트**를 작성해
`bp_ai_consensus_daily` 에 저장하는 작업 가이드입니다.
저장된 리포트는 종합분석 화면(/predict/consensus, AI 예측 상세의 "종합분석" 탭)에 표시됩니다.

## 목적

- 세 AI의 의견(일치/갈림)과 정밀 데이터(선발·타선·불펜·피로·상대전적)를 **하나의 서사로 종합**한 분석을 제공합니다.
- 자동 요약(폴백)과 달리 사람이 읽는 리포트 수준의 해석을 담습니다. 데이터 나열이 아니라 "왜 이 픽이고, 무엇이 승부를 가르고, 어떤 전개가 유력한가"를 서술합니다.

## 역할 분리 (중요)

- 이 작업은 **사후 취합 전용**입니다 — 세 AI의 픽·근거를 모두 조회합니다.
- 따라서 **승리팀 예측을 하는 창(세션)과 분리**해서 수행합니다. 예측 창이 타 AI의 픽·논리를 보면 독립성이 오염됩니다.
- 이 작업은 `bp_ai_predictions` 에 절대 쓰지 않습니다. 쓰는 테이블은 `bp_ai_consensus_daily` 뿐입니다.

## 작업 절차

### 1. 종합픽 산출

```bash
node scripts/consensus-pick.mjs 2026-08-02   # 날짜 = 대상 경기일
```

경기별 3AI 픽·confidence·key_factor 와 종합픽(확률, 만장일치/의견갈림)이 출력됩니다.
3개 AI가 아직 다 입력되지 않은 경기가 있으면 작성하지 말고 운영자에게 알립니다.

### 2. 데이터 수집

```bash
node scripts/analyze-today-games.mjs 2026-08-02
```

7차원 도시에: 선발(시즌+최근 3등판 로그) · 타선(최근 5경기 경기별 득점·홈런·삼진) · 수비(실책) ·
불펜(최근10 ERA/WHIP·피로도) · 시즌 상대전적/홈·원정 스플릿 · 주축 이탈 감지 · 뉴스.

**선수 검증 (필수)** — 리포트에 선수 이름을 쓰기 전 최근 라인업 대조.
"주축 이탈 감지" 경고자는 활약 예상으로 언급 금지(이탈 사실 자체는 근거로 사용 가능).
다른 AI의 key_factor 를 인용할 때도 그 안의 선수명을 같은 기준으로 검증합니다.
(사례: 시즌아웃된 최정을 타 AI 근거에서 그대로 인용했던 사고 — 2026-08-01)

### 3. 리포트 작성 및 저장

`scripts/insert-consensus-analysis.mjs` 의 상단 상수(GAME_DATE, PUBLISHED_AT=그날 09:00 KST,
MODEL=현재 세션 모델)와 ANALYSES 배열을 그날 경기로 재작성 후 실행합니다.
pick/probability/is_unanimous 는 1단계 consensus-pick.mjs 출력값을 그대로 사용합니다.

## 본문 작성 기준 (경기당 4~6문장)

1. **데이터 나열 금지.** 서사 구조: AI 의견 구도(누가 왜 갈렸나) → 데이터 해석(무엇이 승부를 가르나) → 변수 → 결론.
2. 만장일치 경기도 각각 **다른 관점**으로 씁니다 (예: "팀 전력이 아니라 오늘 마운드 두 명에 대한 베팅").
3. 격전지는 **양쪽 논리를 모두 정당하게** 소개한 뒤, 무게추가 기우는 조건을 명시합니다 (예: "한화가 초반에 앞서가지 못하면 뒤로 갈수록 KT").
4. 수치는 괄호로, 전문 약어는 금지 (ERA→평균 자책점, BB9→9이닝당 볼넷, OBP→출루율).
5. **중요 구절 3~5곳을 `**볼드**` 마킹** — 픽 구도·결정 요인·결론. 굵은 부분만 이어 읽어도 결론이 잡히게 (화면이 `<strong>` 으로 렌더).
6. 확률 표현은 배너가 이미 보여주므로 본문에서 반복 설명하지 않아도 됩니다.
7. **마지막은 빈 줄로 구분한 "정리" 1~2문장** (2026-08-15부터) — 이 두 줄만 읽어도 픽과 이유가 잡히게. ① 픽 + 가장 큰 이유 하나 ② 뒤집힐 조건(관전 포인트). **본문 수치를 재나열하지 말 것** — 요약은 판단의 뼈대만. 본문(3~4문장)에서는 결론을 내리지 않고 구도·데이터·변수까지만 쓴 뒤, 결론은 정리 문단에 몰아준다 (중복 방지). 화면은 `whitespace-pre-line` 이라 `\n\n` 이 문단 구분으로 렌더된다.

### 좋은 예 (2026-08-01 한화@KT 격전지)

> **오늘의 최대 격전지**입니다. GPT·Gemini는 최근 열 경기 여덟 번을 이긴 KT의 흐름과 수원 홈을, Claude는 KT 선발 배제성의 제구 결함(9이닝당 볼넷 6개 이상)과 한화 타선의 최다 득점 화력을 근거로 정면으로 갈렸습니다. ... **초반 그림은 한화 쪽**입니다 — ... 그러나 **경기가 뒤로 갈수록 무게추는 KT로 넘어갑니다**. 불펜 최근 10경기 평균 자책점이 KT 2점대 중반 대 한화 6점대 중반으로 격차가 크기 때문입니다. 결국 한화가 초반에 앞서가지 못하면 KT가 뒤집는 전개가 유력하고, 그래서 **51%의 진짜 반반 승부**로 봅니다.

## 화면 동작 참고

- 리포트가 저장되면 종합분석 탭이 본문을 표시합니다. **미작성 시 자동 요약(정형 문장 폴백)** 이 나갑니다.
- 종합픽·확률·만장일치 배지는 화면에서 실시간 계산 — 리포트의 pick/probability 는 작성 시점 기록용입니다.
- 경기 종료 후에는 배너에 적중/실패가 자동 표시됩니다.
- 반영 지연: fetch 캐시 최대 1분.

## 테이블

`bp_ai_consensus_daily` — 경기당 1건, `(game_id)` unique, UPSERT.
