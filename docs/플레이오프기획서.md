# 플레이오프 모드 기획서

작성일: 2026-06-06 · 개정: 2026-06-06 (검토 반영)

## 0. 개정 결정 (검토 반영, 2026-06-06)

아래 결정이 본문보다 우선한다. 본문은 배경/세부 참고용.

1. **공식 전적과 분리** — 플레이오프는 AI 상대 PvE이므로 누적/홈 전적(`source='public'`)에 집계하지 않는다. 별도 `bp_playoff_runs`에만 기록한다.
2. **마이페이지에 우승 기록** — 우승 횟수·최고 도달 라운드 + **우승 팀과 우승 라인업 스냅샷**(명예의 전당)을 마이페이지에 노출한다.
3. **랜덤 대진** — 내 구단 제외 KBO 팀 중 4팀을 매판 랜덤 선택(변화·재플레이성). 순위 기반 시드는 "매번 같은 대진" 문제로 채택하지 않는다. (난이도 상승감이 약하면 추후 *뽑은 4팀만* 전력순 정렬로 보완 — 팀은 계속 바뀜)
4. **진입 조건 완화** — 출전 등록 여부와 무관, **완성 팀(타자 9명 + 선발 1명)** 이면 도전 가능.
5. **플레이오프 전용 임시 라인업** — 진입 시 선택 팀 라인업을 run에 복사하고, 이후 수정은 그 임시본만 건드린다. **실제 운영 팀·경기장 출전 라인업은 무영향.** (본문 5.6의 "팀 관리로 이동"을 대체)
6. **데이터 모델** — MVP는 단일 테이블 `bp_playoff_runs` + `state jsonb`(참가팀·라운드·경기결과 전부) + RLS(owner-only). (본문 6의 3테이블은 추후 분리 옵션)

## 0.1 구현 계획 (컴포넌트 재사용 맵)

AI 대결 플로우(`AiChallengeBody`→`PlayScreen`→`ResultScreen`)가 그대로 템플릿. 시뮬·라인업변환·경기·결과 화면을 재사용하고, 신규는 대진표·임시 편집기·run 상태만.

| 기능 | 재사용 |
|---|---|
| 시뮬 | `simulateGame` (lib/sim/engine.ts) |
| 라인업→시뮬입력 (브릿지) | `buildSimTeamInput` (lib/sim/lineupAdapter.ts) — 내 팀·AI 각각 |
| 투수 자동채움 | `fillMissingPitcherSlots` (lib/sim/autoPitcherLineup.ts) |
| AI 상대 생성 | `buildFakeOpponentTeam` + `applyBlendedStatsToTeam` |
| 최근폼 스탯 | `buildStatsDirectoryWithRecentForm` |
| 세션 | `saveMatchSession`/`loadMatchSession` (source:"playoff" 추가) |
| 경기 화면 | `PlayScreen` (그대로 — source≠public이라 전적 자동저장 안 됨) |
| 결과 화면 | `ResultScreen` + 플레이오프 분기("대진표로") |
| 라인업 편집기 | `BatterSlotList`/`PitcherSlotList`/`LineupDiamond`/`LineupPoolCard` (임의 state 구동) |

신규 파일: `supabase/add-bp-playoff-runs.sql`, `lib/supabase/query-parts/bpPlayoff.ts`, `lib/actions/playoff.ts`, `app/stadium/playoff/page.tsx`, `components/domain/stadium/playoff/{PlayoffHubScreen, PlayoffBracket, PlayoffLineupEditor, OpponentLineupModal}.tsx`, `styles/dark-playoff.css`.

빌드 순서: **1차** SQL+쿼리+액션 → 로비카드·허브·팀선택·startRun → 대진표(보기)·경기시작·PlayScreen → ResultScreen분기·recordGame·상태처리. **2차** 임시 라인업 편집기·상대 라인업 모달. **3차** 마이페이지 가을야구 카드·다전제·포인트·시드정렬.

## 1. 기획 목적

현재 BallPlay는 팀 슬롯과 출전 등록 구조를 통해 유저가 직접 팀을 운영하고, 다른 팀과 시뮬레이션 경기를 할 수 있다. 다만 사용자 수가 적은 초기 단계에서는 유저 간 시즌이나 월간 리그를 바로 열면 참가 팀 부족이 눈에 띄고, 콘텐츠가 비어 보일 수 있다.

플레이오프 모드는 이 문제를 피하면서도 유저에게 명확한 목표를 제공하는 솔로 PvE 콘텐츠다.

- 사용자 수와 무관하게 플레이 가능
- 짧은 경기 수로 목표가 명확함
- 내 팀 라인업을 상대에 맞춰 수정하는 재미 제공
- 추후 솔로 리그, 월간 시즌, 유저 시즌으로 확장 가능

## 2. 핵심 컨셉

유저는 자신의 출전 팀 중 하나를 선택해 5위 팀으로 플레이오프에 진입한다. 이후 AI 4위 팀부터 차례로 상대하며 한국시리즈 우승까지 도전한다.

기본 흐름:

```text
플레이오프 도전
→ 내 출전 팀 선택
→ 대진표 확인
→ 상대 라인업 확인
→ 내 라인업 수정
→ 경기 시작
→ 결과 확인
→ 대진표 복귀
→ 다음 라운드 진행
```

## 3. 진입 위치

초기 버전에서는 홈 메인에 별도 메뉴로 노출하지 않고, 경기장 안에 `플레이오프 도전` 카드로 진입한다.

추천 경기장 구성:

```text
경기장

[플레이오프 도전]
5위에서 시작해 한국시리즈 우승까지 도전

[출전 팀]
다른 유저의 출전 팀과 공식 경기

[랭킹]
공식 경기 순위
```

이유:

- 플레이오프는 라인업 편집이 아니라 경기 모드이므로 경기장 맥락이 자연스럽다.
- 홈 화면이 복잡해지는 것을 막을 수 있다.
- 반응이 좋으면 나중에 홈 카드로 승격할 수 있다.

## 4. MVP 범위

첫 버전은 단판 토너먼트로 구현한다.

- 유저는 5위 팀으로 시작
- AI 4위 팀과 첫 경기
- 승리하면 3위 팀 상대
- 승리하면 2위 팀 상대
- 승리하면 1위 팀과 한국시리즈
- 패배하면 도전 종료
- 한국시리즈 승리 시 우승 처리

MVP 라운드:

| 라운드 | 상대 | 방식 |
|---|---|---|
| 4·5위전 | AI 4위 팀 | 단판 |
| 준플레이오프 | AI 3위 팀 | 단판 |
| 플레이오프 | AI 2위 팀 | 단판 |
| 한국시리즈 | AI 1위 팀 | 단판 |

추후 확장:

- 와일드카드 단판
- 준플레이오프 3전 2선승
- 플레이오프 5전 3선승
- 한국시리즈 7전 4선승

## 5. 플레이 흐름

### 5.1 플레이오프 진입

유저가 경기장 화면에서 `플레이오프 도전`을 선택한다.

진입 조건:

- 출전 등록된 팀이 1개 이상 있어야 한다.
- 출전 준비 상태 팀은 선택할 수 없다.
- 필수 조건은 기존 출전 등록 기준과 동일하다.
  - 타자 9명
  - 선발 투수 1명

출전 등록 팀이 없을 경우:

```text
출전 팀이 필요해요
플레이오프에 도전하려면 출전 등록된 팀이 있어야 해요.
팀 관리에서 타자 9명과 선발 투수를 채운 뒤 출전 등록을 해주세요.

[팀 관리로 이동]
```

### 5.2 내 팀 선택

유저는 자신의 출전 팀 중 하나를 선택한다.

표시 정보:

- 팀명
- 구단
- 홈 전적
- 최근 경기 결과
- 출전 상태

선택 후 `도전 시작`을 누르면 플레이오프 세션이 생성된다.

### 5.3 AI 상대 팀 생성

내가 선택한 구단을 제외한 KBO 팀 중 4개 팀을 AI 상대로 배정한다.

초기 MVP 방식:

- 내 팀 구단 제외
- 나머지 팀 중 4개 랜덤 선택
- 4위, 3위, 2위, 1위로 배정

추후 개선:

- 실제 KBO 순위 반영
- 팀 전력 기반 시드 배정
- 난이도별 상대 강화
- 최근 실제 경기 라인업 반영

### 5.4 대진표 화면

대진표 화면은 플레이오프 모드의 중심 화면이다.

필수 표시:

- 현재 라운드
- 내 팀
- 현재 상대 팀
- 다음 라운드 상대
- 완료된 라운드 결과
- 현재 도전 상태

예시:

```text
가을야구 도전

현재 라운드
4·5위전

5위 야구노리의 롯데
vs
4위 AI 두산

[상대 라인업 보기]
[내 라인업 수정]
[경기 시작]
```

상태별 버튼:

- 진행 전: `경기 시작`
- 승리 후: `다음 라운드`
- 패배 후: `재도전`
- 우승 후: `우승 기록 보기`

### 5.5 상대 라인업 확인

경기 시작 전 상대 AI 팀 라인업을 볼 수 있다.

표시 정보:

- 상대 팀명
- 선발 투수
- 타순 1~9번
- 주요 타자 2~3명
- 간단 전력 요약

MVP에서는 기존 `LineupDetailModal` 또는 유사 UI를 재사용한다.

### 5.6 내 라인업 수정

플레이오프 진행 중에도 내 라인업 수정은 허용한다.

정책:

- 경기 시작 전까지 자유롭게 수정 가능
- 이미 끝난 경기 결과에는 영향 없음
- 다음 경기부터 최신 라인업 적용
- 경기 시작 시점에 내 라인업 스냅샷 저장

MVP에서는 플레이오프 전용 편집 UI를 만들지 않는다.

버튼:

```text
[내 라인업 수정]
```

동작:

- 기존 `팀 관리` 화면으로 이동
- 수정 후 플레이오프 화면으로 돌아올 수 있게 `next` 또는 local state 처리 고려

### 5.7 경기 시작

유저가 `경기 시작`을 누르면 다음을 고정한다.

- 내 팀 라인업 스냅샷
- 상대 AI 팀 라인업 스냅샷
- 라운드 정보
- seed

이후 기존 경기 시뮬레이션 화면을 재사용한다.

### 5.8 결과 처리

경기 종료 후 결과 화면을 보여준다.

승리:

- 현재 라운드 승리 처리
- 다음 라운드 활성화
- 대진표 복귀

패배:

- 플레이오프 도전 종료
- 최고 도달 라운드 기록
- 재도전 버튼 제공

우승:

- 한국시리즈 우승 처리
- 우승 기록 저장
- 보상 또는 배지 지급 가능

## 6. 데이터 설계 초안

### 6.1 bp_playoff_runs

플레이오프 도전 1회를 나타낸다.

컬럼 초안:

```text
id uuid primary key
user_id uuid
lineup_id uuid
entry_id text
team_id text
team_name text
status text -- active, completed, eliminated, abandoned
current_round text -- wildcard, semi_playoff, playoff, korean_series
result text -- champion, eliminated, abandoned, null
created_at timestamptz
updated_at timestamptz
completed_at timestamptz
```

### 6.2 bp_playoff_teams

플레이오프에 참가하는 내 팀과 AI 팀 목록.

```text
id uuid primary key
run_id uuid
seed int -- 1,2,3,4,5
team_id text
team_name text
is_user_team boolean
lineup_snapshot jsonb
created_at timestamptz
```

### 6.3 bp_playoff_games

라운드별 경기.

```text
id uuid primary key
run_id uuid
round text
home_seed int
away_seed int
home_team_id text
away_team_id text
home_lineup_snapshot jsonb
away_lineup_snapshot jsonb
status text -- scheduled, playing, finished
result jsonb
winner_seed int
played_at timestamptz
created_at timestamptz
```

MVP에서는 테이블을 줄이고 `bp_playoff_runs.state jsonb`에 전체 상태를 저장할 수도 있다. 다만 추후 기록/통계/재개 기능을 고려하면 테이블 분리가 더 안전하다.

## 7. AI 라인업 생성

우선순위:

1. 최근 실제 경기 라인업 사용
2. 없으면 자동 베스트 라인업 생성
3. 없으면 로스터 기반 기본 라인업 생성

MVP에서는 현재 프로젝트의 실제 경기 라인업 불러오기/로스터 기반 자동 채움 로직을 최대한 재사용한다.

상대 AI 팀은 사용자 팀과 동일한 시뮬레이션 입력 구조로 변환되어야 한다.

## 8. 보상 설계

MVP에서는 보상 없이 기록만 저장해도 된다.

초기 기록:

- 최고 도달 라운드
- 우승 횟수
- 플레이오프 전적
- 사용한 팀
- 우승 라인업 스냅샷

포인트 기능 도입 후:

| 결과 | 보상 예시 |
|---|---|
| 4·5위전 승리 | 소량 포인트 |
| 준플레이오프 승리 | 포인트 |
| 플레이오프 승리 | 포인트 |
| 한국시리즈 우승 | 큰 포인트 + 배지 |

참가비는 초기에는 두지 않는 것을 추천한다.

## 9. UX 원칙

- 목표는 짧고 명확해야 한다.
- 한 번 지면 탈락이므로 긴장감을 준다.
- 상대 라인업을 보고 내 라인업을 수정할 수 있어야 한다.
- 경기 시작 시점 스냅샷으로 공정성을 유지한다.
- 패배해도 바로 재도전할 수 있어야 한다.
- 사용자 수가 적어도 콘텐츠가 비어 보이지 않아야 한다.

## 10. 구현 우선순위

### 1차 MVP

- 경기장에 `플레이오프 도전` 카드 추가
- 내 출전 팀 선택 화면
- AI 4팀 생성
- 대진표 화면
- 상대 라인업 보기
- 기존 팀 관리로 라인업 수정 이동
- 단판 경기 진행
- 결과 후 대진표 복귀
- 패배/우승 상태 처리

### 2차

- 플레이오프 기록 저장
- 최고 도달 라운드 표시
- 우승 기록 보관
- 재도전 UX 개선

### 3차

- 다전제 라운드
- 포인트 보상
- 난이도 선택
- 실제 KBO 순위 기반 시드
- 포스트시즌 히스토리

## 11. 오픈 전략

처음에는 홈 메인에 크게 노출하지 않고 경기장 내부 카드로 시작한다.

반응이 좋으면 홈에 별도 카드로 승격한다.

홈 카드 예시:

```text
가을야구 도전
5위의 기적을 만들어보세요.
```

## 12. 결정된 방향 요약

- 유저 간 월간 시즌보다 플레이오프 솔로 모드를 먼저 고려한다.
- 이유는 사용자 수가 적어도 콘텐츠가 비어 보이지 않기 때문이다.
- 첫 버전은 5위에서 시작하는 단판 토너먼트로 간다.
- 내 출전 팀 중 하나를 선택해 도전한다.
